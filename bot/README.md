# BTC Long/Short Spread Bot — Variational ⇄ RISEx

Бот, що відстежує спред ціни BTC-PERP між **Variational (Omni)** і **RISEx
(rise.trade)** і, коли спред перевищує поріг, відкриває **лонг на дешевшій
біржі та шорт на дорожчій** (класичний perp-basis арбітраж), а закриває обидві
ноги, коли спред стискається.

## ⚠️ Перш ніж щось вмикати — прочитайте це

### 1. Це не готовий "просто запустив і заробив" бот

На момент написання коду обидва адаптери бірж (`src/adapters/variational.js`,
`src/adapters/risex.js`) — **заглушки**. Причини:

- **Variational**: офіційний SDK (`variational-sdk-python` на GitHub) прямо
  каже, що самостійна видача API-ключів наразі недоступна — доступ
  видається лише за запитом на **hello@variational.io**. Без ключа й без
  повної специфікації методів підключити цю біржу неможливо.
- **RISEx**: я не зміг перевірити з середовища, де писався цей код, точний
  REST/WS API, формат автентифікації й ендпоінти (сайт документації був
  недоступний з тієї мережі). Відомо, що комісії 0.03% taker / 0.01% maker, і
  що є "sub-accounts" з делегованим виконанням — але вгадувати exact-формат
  запиту, який рухає гроші, я свідомо не став.

Кожен адаптер має прапорець `implemented = false`. **Поки хоч один
`false` — бот примусово працює в режимі DRY-RUN, незалежно від того, що
написано в `.env`.** Він тільки логує "що б зробив" і надсилає сповіщення —
жодного реального ордера не виставить. Це навмисний запобіжник.

### 2. Щоб підключити реальну торгівлю

1. **Variational**: напишіть на hello@variational.io, отримайте API-ключ і
   документацію методів. Їхній офіційний SDK — на Python
   (`pip install variational`), а цей бот на Node.js — тобто або пишете
   виклики їхнього REST API напряму в `variational.js` (якщо є HTTP API поза
   SDK), або піднімаєте окремий малий Python-міст. Заповніть
   `getBookTicker` / `openMarket` / `closePosition` і поставте
   `this.implemented = true`.
2. **RISEx**: зайдіть у свій акаунт на rise.trade → знайдіть розділ API/ключі.
   Платформи майже завжди показують робочий приклад коду одразу після
   створення ключа ("Quickstart") — скопіюйте звідти base URL, заголовки
   авторизації й формат запиту, вставте в `risex.js`, поставте
   `this.implemented = true`.
3. Запустіть спочатку з `LIVE_TRADING=false` (dry-run) і подивіться на лог
   кілька годин/днів — переконайтесь, що ціни коректні, спред рахується
   правильно, а поріг адекватний реальному ринку.
4. Тільки після цього ставте `LIVE_TRADING=true`.

### 3. Ключі та гаманець — НІКОЛИ в чат і НІКОЛИ в git

- `.env` вже в `.gitignore` — не видаляйте цей рядок.
- Якщо RISEx вимагає підпис транзакцій приватним ключем гаманця (а не
  API-ключ) — **створіть окремий гаманець спеціально для бота**, ніколи не
  використовуйте основний. Профінансуйте його лише сумою, якою готові
  ризикувати повністю. Якщо платформа підтримує sub-account/делегований
  підписант з обмеженими правами (без виводу коштів) — використовуйте це
  замість кореневого ключа.
- Ніколи не вставляйте приватний ключ чи API-секрет у переписку з Claude чи
  будь-де поза `.env` на вашому власному сервері.

## Чому поріг 0.20%, а не "будь-який спред"

Реальна вартість round-trip (відкрити + закрити обидві ноги):

| Складова | Variational | RISEx |
|---|---|---|
| Maker | 0% | 0.01% |
| Taker | 0% | 0.03% |

Worst case (обидві ноги виконуються як taker, і відкриття, і закриття):
`2 × 0% + 2 × 0.03% = 0.06%`. Це видає й сам бот при старті
(`roundTripCostPct`).

Але окрім явних комісій є:
- **Leg risk** — ноги відкриваються не атомарно; поки друга виконується,
  ціна могла зрушитись не на вашу користь.
- **RFQ-спред Variational** — 0% комісія не означає 0% вартості: LP
  закладає свій edge у котирування. Реальний розмір цього спреду не
  перевірявся емпірично.
- **Funding rate** — поки позиція відкрита, ви платите/отримуєте funding з
  обох боків; це може як допомогти конвергенції спреду, так і з'їсти
  прибуток, якщо триматимете позицію довго.

Тому дефолт `MIN_SPREAD_PCT=0.20` — з запасом. `CLOSE_SPREAD_PCT=0.03` —
закривати, коли спред практично зійшовся. **Обидва числа підкрутіть після
кількох днів спостережень у dry-run**, коли побачите реальну поведінку
спреду й фактичний RFQ-спред Variational.

## Запуск

Без зовнішніх залежностей — тільки вбудований Node.js (потрібен Node ≥18
заради глобального `fetch`).

```bash
cd bot
cp .env.example .env   # заповніть після підключення адаптерів
node src/index.js
```

Логи пишуться і в консоль, і у файл `logs/bot.log`. Стан відкритої позиції
та денний PnL зберігаються в `data/state.json` (переживає перезапуск).

## Структура

```
bot/
  src/
    config.js        — читає .env, дефолти, комісії
    logger.js         — консоль + файл
    notify.js         — опційний Telegram-алерт
    spreadEngine.js    — розрахунок спреду/арбітражу/вартості round-trip
    riskManager.js      — денний ліміт збитку, ліміт відкритих позицій
    positionStore.js     — персистентний стан (data/state.json)
    adapters/
      base.js            — контракт адаптера
      variational.js       — ЗАГЛУШКА, потребує API-доступу від Variational
      risex.js               — ЗАГЛУШКА, потребує точних ендпоінтів RISEx
    index.js                  — головний цикл
```

## Аварійна зупинка

`Ctrl+C` зупиняє бота одразу (SIGINT). Це **не** закриває вже відкриті на
біржах позиції автоматично — перевірте акаунти вручну після зупинки, якщо
`LIVE_TRADING` була `true`.
