# BTC Long/Short Spread Bot — Nado ⇄ RISEx

Бот, що відстежує спред ціни BTC-PERP між **Nado Protocol** (docs.nado.xyz) і
**RISEx** (rise.trade) і, коли спред перевищує поріг, відкриває **лонг на
дешевшій біржі та шорт на дорожчій** (класичний perp-basis арбітраж), а
закриває обидві ноги, коли спред стискається.

## ⚠️ Перш ніж щось вмикати — прочитайте це

### 1. Це не готовий "просто запустив і заробив" бот

На момент написання коду обидва адаптери бірж (`src/adapters/nado.js`,
`src/adapters/risex.js`) мають `implemented = false`. Причини:

- **Nado**: у документації (docs.nado.xyz) і офіційному TypeScript SDK
  (`@nadohq/client` на GitHub) знайдено конкретні деталі — REST gateway
  (`https://gateway.prod.nado.xyz/v1`), формат ордера (EIP-712, priceX18,
  sender/nonce/expiration), метод розміщення ордера через
  `engineClient.payloadBuilder.buildPlaceOrderPayload(...)`, комісії (Entry
  Tier: 0.035% taker / 0.01% maker). **Але** з мережі, де писався цей бот,
  жоден запит до `gateway.prod.nado.xyz` не пройшов (заблоковано політикою
  того середовища), тож точні назви полів у відповідях (наприклад, як саме
  записано символ BTC-перпа в `all_products`) не підтверджені емпірично.
  Код у `nado.js` написаний за документацією й, найімовірніше, дуже
  близький до робочого — треба лише один прогін і звірка сирих відповідей
  (вони й так друкуються в лог).
- **RISEx**: комісії підтверджено (0.03% taker / 0.01% maker), але точний
  REST/WS API (base URL, автентифікація, ендпоінти ордерів) перевірити не
  вдалось — офіційна документація була недоступна з того ж середовища.

Кожен адаптер має прапорець `implemented = false`. **Поки хоч один
`false` — бот примусово працює в режимі DRY-RUN, незалежно від того, що
написано в `.env`.** Він тільки логує "що б зробив" і надсилає сповіщення —
жодного реального ордера не виставить. Це навмисний запобіжник.

### 2. Щоб підключити реальну торгівлю

1. **Nado**:
   - `cd bot && npm install @nadohq/client ethers`
   - Створіть окремий гаманець спеціально для бота (не основний),
     профінансуйте лише сумою ризику, покладіть приватний ключ у
     `.env` → `NADO_WALLET_PRIVATE_KEY`.
   - Запустіть бота в dry-run і подивіться в лог, що реально повертають
     `all_products` і `all_bbo` (адаптер друкує сирі відповіді) — звірте з
     тим, що читає код у `_resolveProductId()`/`getBookTicker()`, поправте
     назви полів, якщо відрізняються.
   - Звірте сигнатуру конструктора `NadoClient` на
     https://nadohq.github.io/nado-typescript-sdk/ — у коді зараз
     найбільш імовірний варіант за документацією, не 100% підтверджений.
   - Заповніть `openMarket`/`closePosition` за прикладом у коментарях і
     поставте `this.implemented = true`.
2. **RISEx**: зайдіть у свій акаунт на rise.trade → знайдіть розділ API/ключі.
   Платформи майже завжди показують робочий приклад коду одразу після
   створення ключа ("Quickstart") — скопіюйте звідти base URL, заголовки
   авторизації й формат запиту, вставте в `risex.js`, поставте
   `this.implemented = true`.
3. Запустіть спочатку з `LIVE_TRADING=false` (dry-run) і подивіться на лог
   кілька годин/днів — переконайтесь, що ціни коректні, спред рахується
   правильно, а поріг адекватний реальному ринку.
4. Тільки після цього ставте `LIVE_TRADING=true`.

### 3. Ключі та гаманець — НІКОЛИ в чат і НІКОЛИ в git

- `.env` вже в `.gitignore` — не видаляйте цей рядок.
- Nado підписує ордери гаманцем (EIP-712) — **обов'язково окремий гаманець
  для бота**, ніколи основний, профінансований лише сумою, якою готові
  ризикувати повністю.
- Якщо RISEx теж вимагає підпис транзакцій приватним ключем (а не
  API-ключ) — те саме правило: окремий гаманець, мінімальний баланс. Якщо
  платформа підтримує sub-account/делегований підписант з обмеженими
  правами (без виводу коштів) — використовуйте це замість кореневого ключа.
- Ніколи не вставляйте приватний ключ чи API-секрет у переписку з Claude чи
  будь-де поза `.env` на вашому власному сервері.

## Чому поріг 0.25%, а не "будь-який спред"

Реальна вартість round-trip (відкрити + закрити обидві ноги), за
задокументованими комісіями обох платформ:

| Складова | Nado (Entry Tier) | RISEx |
|---|---|---|
| Maker | 0.01% | 0.01% |
| Taker | 0.035% | 0.03% |

Worst case (усі 4 виконання — і відкриття, і закриття обох ніг — як taker):
`2 × 0.035% + 2 × 0.03% = 0.13%`. Best case (усе maker'ом, що не завжди
можливо для миттєвого входу): `2 × 0.01% + 2 × 0.01% = 0.04%`. Це видає й
сам бот при старті (`roundTripCostPct`).

Окрім явних комісій є ще:
- **Leg risk** — ноги відкриваються не атомарно; поки друга виконується,
  ціна могла зрушитись не на вашу користь.
- **Funding rate** — поки позиція відкрита, ви платите/отримуєте funding з
  обох боків; це може як допомогти конвергенції спреду, так і з'їсти
  прибуток при довгому утриманні.
- **Обсяг-тир Nado** — 0.035% taker це найгірший (Entry) тариф; якщо у вас
  вищий обсяг торгів, комісія нижча — перевірте свій реальний тариф
  запитом `fee-rates` і за потреби зменште `MIN_SPREAD_PCT`.

Тому дефолт `MIN_SPREAD_PCT=0.25` — з запасом понад worst-case 0.13%.
`CLOSE_SPREAD_PCT=0.05` — закривати, коли спред практично зійшовся.
**Обидва числа підкрутіть після кількох днів спостережень у dry-run.**

## Запуск

Базово — без зовнішніх залежностей (тільки вбудований Node.js, потрібен
Node ≥18 заради глобального `fetch`). Пакети `@nadohq/client` і `ethers`
знадобляться лише коли реально підключатимете `nado.js`.

```bash
cd bot
cp .env.example .env   # заповніть після підключення адаптерів
node src/index.js
```

Логи пишуться і в консоль, і у файл `logs/bot.log`. Стан відкритої позиції
та денний PnL зберігаються в `data/state.json` (переживає перезапуск).

## Структура

```
bot/
  src/
    config.js        — читає .env, дефолти, комісії
    logger.js         — консоль + файл
    notify.js         — опційний Telegram-алерт
    spreadEngine.js    — розрахунок спреду/арбітражу/вартості round-trip
    riskManager.js      — денний ліміт збитку, ліміт відкритих позицій
    positionStore.js     — персистентний стан (data/state.json)
    adapters/
      base.js            — контракт адаптера
      nado.js              — написано за документацією, потребує 1 звірки полів
      risex.js               — ЗАГЛУШКА, потребує точних ендпоінтів RISEx
    index.js                  — головний цикл
```

## Аварійна зупинка

`Ctrl+C` зупиняє бота одразу (SIGINT). Це **не** закриває вже відкриті на
біржах позиції автоматично — перевірте акаунти вручну після зупинки, якщо
`LIVE_TRADING` була `true`.
