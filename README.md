# BTC Spread Monitor — усі біржі

Односторінковий сайт (без бекенду), який у реальному часі показує ціну BTC
одразу на ~20 біржах і сигналізує (звук + push-сповіщення браузера + запис у
журнал), коли спред між будь-якою парою бірж перевищує заданий поріг (за
замовчуванням 2%).

## Біржі в списку

Binance, Aster, Coinbase, OKX, Bybit, Bitget, Gate, KuCoin, MEXC, HTX,
Crypto.com, Bitfinex, BingX, Kraken, Binance TR, LBank, Bitstamp, Bithumb,
XT.COM, Backpack.

Додати ще одну — див. розділ [Як додати біржу](#як-додати-біржу).

## Як це працює

- **Binance і Aster** — напряму через WebSocket bookTicker-потоки
  (`wss://fstream.binance.com/...`, `wss://fstream.asterdex.com/...`):
  найкращі bid/ask у реальному часі, без затримки.
- **Решта бірж** — через REST-опитування їхніх публічних тікер/orderbook
  ендпоінтів раз на ~1.5–2с (більшість не мають простого публічного
  WebSocket без токена підписки, тож REST — надійніший спільний знаменник).
- Кожна біржа працює повністю незалежно: якщо якийсь ендпоінт недоступний
  (див. нижче про CORS), тимчасово заблокований по гео чи змінив формат
  відповіді — ця біржа просто показує статус «офлайн» у таблиці й не заважає
  іншим.
- Спред рахується по **всіх парах бірж одночасно**: на верхній картці
  показано найбільший поточний спред (mid-price) серед усіх «живих» бірж —
  тобто різницю між найдешевшою і найдорожчою біржею просто зараз — а також
  виконуваний арбітражний спред для цієї ж пари (купити по ask дешевшої,
  продати по bid дорожчої).
- Поріг сповіщення і курс USD/KRW (для Bithumb) можна міняти прямо на
  сторінці. Кожне спрацювання потрапляє в журнал знизу.

## Нормалізація валют (важливо)

- **USDT / USDC / USD** прирівнюються одне до одного як ≈$1. Це стандартне
  спрощення для виявлення спреду; воно ігнорує дрібний базис-ризик між
  стейблкоїнами (зазвичай соті частки відсотка).
- **Bithumb** квотує в KRW. Ціна ділиться на курс USD/KRW із поля вводу
  (за замовчуванням 1400) — це вручну задане наближення, а не жива
  котирування Forex, тому спред по Bithumb варто сприймати як орієнтовний,
  доки ви не поставите точний курс.

## CORS: чому якась біржа може показувати «офлайн»

Сторінка звертається до API бірж напряму з браузера. Деякі біржі не
дозволяють такі запити з чужих доменів (CORS) для певних ендпоінтів — тоді
браузер мовчки блокує відповідь, і рядок біржі просто лишається «офлайн»,
з автоматичними повторними спробами. Це не помилка сайту — обхід
потребував би невеликого проксі-сервера (наприклад, Cloudflare Worker),
який тут свідомо не додано, щоб сайт лишався простим статичним HTML без
бекенду.

## Запуск

Це статичний сайт (`index.html` + `style.css` + `app.js`), бекенд не потрібен.

### Локально
Відкрийте `index.html` у браузері (подвійний клік або `open index.html`).

### Хостинг
- **GitHub Pages**: Settings → Pages → Deploy from branch → оберіть цю гілку
  і корінь репозиторію.
- **Netlify / Vercel**: перетягніть папку з файлами в інтерфейс деплою.

## Як додати біржу

У `app.js` є масив `EXCHANGES`. Додайте новий об'єкт:

```js
{
  id: "myexchange",
  name: "MyExchange",
  quote: "USDT",
  mode: "rest", // або "ws", якщо є прямий WebSocket bookTicker
  rest: "https://.../ticker?symbol=BTCUSDT",
  parseRest: (json) => ({ bid: parseFloat(json.bid), ask: parseFloat(json.ask) }),
}
```

Решта (опитування, статус, спред, алерти) підхопиться автоматично.

## Обмеження

- Binance інколи недоступний з деяких країн (гео-обмеження) — допоможе VPN
  або хостинг сторінки в іншому регіоні.
- Для звукових сповіщень потрібна хоча б одна взаємодія користувача зі
  сторінкою (клік) — стандартне обмеження браузерів.
- Push-сповіщення вимагають дозволу браузера.
- Символ за замовчуванням — BTC до USDT/USD/USDC/KRW залежно від біржі.
